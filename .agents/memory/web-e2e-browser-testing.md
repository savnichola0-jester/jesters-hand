---
name: Web E2E browser testing recipe
description: How to drive the Expo web app end-to-end with Playwright + system chromium against the live Firebase project.
---
- Playwright-core + nix `chromium` (`--no-sandbox`) against the Expo dev server port works; RN-web has no testIDs, so target exact visible text/placeholders. Home tiles are IMAGES (`img[src*="tile_7"]` = Vault) — labels are baked into the PNGs, not DOM text.
- Login: placeholders `Enter Joker ID...` / `Enter Cipher...`, button `Take a Seat`. First login hits the Contract gate: fill fields AND draw on the signature pad with mouse drags below the `SIGNATURE` label or `SIGN & ENTER THE HAND` is a no-op.
- Cold-load deep links (`/vault?...` in a fresh tab) bounce to the lock screen: screens do `if (user === null) router.replace('/')` and AuthContext starts with `user = null` before Firebase restores the session. Test deep links **in-app** (bell taps) instead; the cold-start bounce is a real product limitation.
- `getByText(...).isVisible()` throws on multiple matches (strict mode) → silent false in `.catch(()=>false)` guards; always `.first()`.
- Combine with the prod-smoke-testing recipe: throwaway signUp accounts, owner-token admin elevation, seed a published vault entry + a **valid** PDF (pdf.js rejects hand-written PDFs without a correct xref table), fail-safe cleanup of docs/storage/auth at the end.
- Reaction toggles are idempotent-toggling: rerunning a script un-reacts. Reseed a fresh entry per full run.
- Negative "button absent" assertions: non-exact `getByText("RESTORE")` matches case-insensitively as a substring, so it hits explanatory copy like "can restore or permanently delete" and false-fails. Use a case-sensitive regex (`/^RESTORE$/`) or `exact: true` for absence checks. Admin-panel section tabs render `label.toUpperCase()` — target 'ARCHIVE', not 'Archive'.
- **MANDATORY cleanup before finishing:** every test run MUST delete its throwaway accounts and seeded content before it ends (auth account, users doc, seeded vault entries) — leftover "E2E Tester" accounts have shown up in the live roster (The Hand) twice. Wrap the run so cleanup executes even when assertions fail. Safety net / sweep for leftovers: `cd artifacts/api-server && node scripts/purge-testers.mjs --dry-run` (then without the flag) — removes accounts with out-of-range Joker IDs (real range: 00-00, 01-54…54-54) or E2E/tester names via the full wipe manifest, plus E2E-titled vault entries. It deliberately ignores legacy `@jestershand.app` auth accounts.
- A complete live-data sweep must also remove tester contract archives, `sessions/{testUid}/logs`, and E2E Vault activity rows; deleting only auth/users/agreements leaves these visible. Never classify the real 00-00 Jester account as a tester merely because it viewed E2E content—delete the E2E activity row, not that account.
- Contract-gate signature pad: it's a large react-native-svg element that starts BELOW the fold — `scrollIntoViewIfNeeded()` on the big (>200px wide) svg before mouse-drawing, or strokes land on nothing and SIGN is a silent no-op.
- Jester's Table channel names repeat: text and voice channels share labels ("SIDE DECK") — use `.last()` (voice section is second) or target unique voice-only text.
- Published-site voice E2E works headless: launch chromium with `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream` + mic permission; "at the table" text confirms Agora join.
